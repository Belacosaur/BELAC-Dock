# Security and privacy

The dock runs with the current user's permissions. Dock-only changes are opt-in and journaled for recovery. The compatibility fallback changes window styles and may remove Alt+Tab entries. Elevated/protected apps can remain unsupported.

Native usage reads existing Codex/Claude Code credential files and Cursor's local SQLite sign-in store in read-only mode. Encrypted Cursor credentials are decoded locally using its Local State key protected by the current Windows account; decrypted keys and temporary plaintext buffers are cleared after use. Access tokens are held in memory and sent only to their fixed HTTPS provider endpoint; redirects are disabled. The dock does not modify provider credential stores, store tokens in its settings, or log request headers/response bodies. Cursor access tokens can be renewed using its existing refresh credential; renewed tokens remain in memory and are discarded when the source account changes. Codex and Claude renewals remain owned by their apps. Optional OpenTokenUsage fallback uses only http://127.0.0.1:6736. The dock does not collect analytics. Settings and diagnostic exports may include private executable paths, window titles and app names. Review and redact them before sharing. Do not attach a live recovery journal or raw configuration to a public issue.

Use the hosting repository's private vulnerability reporting feature if enabled; otherwise contact its maintainer privately before publishing exploit details. Maintainers should enable private vulnerability reporting before opening the repository. Only current releases are maintained. Archives are unsigned unless explicitly stated otherwise.
